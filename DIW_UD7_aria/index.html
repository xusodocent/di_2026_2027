    Aquest apartat aplica RA4.c–f, h–i de DAM a navegació, controls i missatges accessibles. ARIA és una tecnologia d’accessibilitat; no és una interfície natural de veu, gestos o realitat augmentada de RA2. Consulta el mapa de continguts i RA de DAM.

    ARIA per a accessibilitat

    1. Què aporta ARIA?

    ARIA comunica noms, rols, estats i relacions a les tecnologies d’assistència. No afig automàticament clics, teclat, focus ni validació. Prioritza els controls HTML natius.

    HTML
    1
2
    <label><input type="checkbox" name="ofertes"> Rebre ofertes</label>
<button type="button">Guardar</button>

    Un <div role="button" tabindex="0"> només anuncia un rol i rep focus: encara necessitaria implementar l’activació amb teclat. Igualment, checked no és un atribut vàlid d’un <li>.

    2. Nom accessible

    El text visible sol proporcionar el nom d’un botó. Usa aria-label quan el control no tinga text visible i aria-labelledby per referenciar un text existent.

    HTML
    1
2
3
4
5
    <button type="button" aria-label="Tancar">×</button>
<section aria-labelledby="titol-productes">
  <h2 id="titol-productes">Productes</h2>
  <p>Consulta el catàleg.</p>
</section>

    No substituïsques un text visible clar per una etiqueta diferent. aria-describedby associa informació complementària, no el nom principal.

    3. Estats i comportament

    • aria-expanded comunica si el contingut controlat està desplegat. El codi ha de sincronitzar-lo amb la visibilitat.
    • aria-checked descriu una casella personalitzada. En un <input type="checkbox"> usa l’estat natiu checked.
    • aria-disabled="true" anuncia indisponibilitat però no bloqueja l’activació. En un botó natiu usa disabled si vols desactivar-lo amb el comportament del navegador.
    • aria-hidden="true" exclou contingut de l’arbre d’accessibilitat; no l’amaga visualment. No l’apliques a controls enfocables ni als seus contenidors.

<script>
  const boto = document.querySelector('#obrir-menu');
  const navegacio = document.querySelector('#navegacio');
  boto.addEventListener('click', () => {
    const obrir = boto.getAttribute('aria-expanded') !== 'true';
    boto.setAttribute('aria-expanded', String(obrir));
    navegacio.hidden = !obrir;
  });
  navegacio.addEventListener('keydown', (event) => {
    if (event.key === 'Escape') {
      navegacio.hidden = true;
      boto.setAttribute('aria-expanded', 'false');
      boto.focus();
    }
  });
</script>

    4. Regions vives

    Per a resultats no urgents usa role="status". Crea la regió abans d’actualitzar-ne el text; no cal moure-hi el focus.

    HTML
    1
    <p id="resultat" role="status"></p>
    JavaScript
    1
    document.querySelector('#resultat').textContent = 'S’han carregat 12 resultats.';

    role="alert" té un anunci assertiu implícit; reserva’l per a missatges urgents. La manera exacta d’anunciar depén del navegador i del lector de pantalla.

    5. Ordre del focus

    tabindex="0" incorpora un element a l’ordre natural. tabindex="-1" permet donar-li focus per codi sense afegir-lo al recorregut de Tab. Evita valors positius: s’avancen als elements amb 0 i poden separar l’ordre de teclat del visual.

    Els botons i enllaços amb href ja reben focus sense tabindex. Els botons s’activen amb Enter o Espai; els enllaços, amb Enter.

    HTML

    <form aria-labelledby="form-title">
  <h2 id="form-title">Subscripció</h2>
  <label for="email">Correu electrònic (obligatori)</label>
  <input type="email" id="email" name="email" required
         autocomplete="email" aria-describedby="email-help">
  <p id="email-help">Usarem aquesta adreça per enviar el butlletí.</p>
  <button type="submit">Subscriu-te</button>
</form>

    required activa la validació nativa; aria-required per si sol no ho fa. L’enviament real necessita una destinació o un controlador, que no forma part d’aquest fragment.
